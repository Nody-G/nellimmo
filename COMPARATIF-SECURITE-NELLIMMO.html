Le Clickjacking (Détournement Clandestin de Clic)

En-tête X-Frame-Options & CSP
🎯 Vulgarisation & Risque Métier
Risque Réputationnel & Fraude : Élevé

Qu'est-ce que c'est ? Le Clickjacking est une technique où un escroc charge le site web de Nell'Immo à l'intérieur de sa propre page malveillante, mais de façon 100% invisible (comme un calque transparent posé par-dessus son site). Par-dessus ce calque invisible, le pirate affiche un faux bouton séduisant (par exemple : « Cliquez ici pour estimer votre bien à +20% » ou « Confirmez votre numéro de téléphone »). Quand le visiteur clique sur le bouton visible de l'escroc, son clic traverse le calque et valide en réalité une action sur le site Nell'Immo à son insu.

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Un faux site immobilier concurrent ou une plateforme de phishing encapsule le formulaire de contact ou l'interface de Nell'Immo. Un internaute pense s'inscrire à une newsletter locale, mais son clic envoie une fausse demande de mandat, soumet des informations erronées ou déclenche des actions administratives si Nelly naviguait en même temps sur son back-office.

📉 Impact Commercial : Perte de crédibilité et plaintes de clients piégés.
⚖️ Impact Juridique : Responsabilité engagée si le site sert de vecteur d'attaque.
Ancien Site (www.nellimmo.fr) Vulnérable

Le serveur de La Boîte Immo n'envoie aucune consigne de protection aux navigateurs. Le site peut être librement encapsulé dans une <iframe> pirate sur n'importe quel domaine du monde. 

# En-têtes prélevés sur l'ancien site :
HTTP/1.1 200 OK
server: Apache
X-Frame-Options: [ABSENT !]
Content-Security-Policy: [ABSENT !]
--> Aucune protection : le site peut être détourné !
Nouveau Nell'Immo (Vercel) Protection Maximale A+

Le serveur Next.js ordonne formellement à tous les navigateurs de la planète d'interdire l'affichage du site dans une fenêtre tierce via la politique de sécurité de contenu (CSP). 

# En-têtes prélevés en direct sur le nouveau site :
HTTP/1.1 200 OK
X-Frame-Options: DENY
Content-Security-Policy: frame-ancestors 'none';
--> Tout affichage dans un cadre externe est bloqué net !

Le Vol de Session Utilisateur (Usurpation d'Identité)

Cookie PHPSESSID sans HttpOnly / Secure
🎯 Vulgarisation & Risque Métier
Risque de Confidentialité & RGPD : Critique

Qu'est-ce que c'est ? Lorsqu'une personne navigue sur un site ou se connecte, le serveur lui attribue un « cookie de session », qui est l'équivalent d'un badge d'accès temporaire. Sur l'ancien site, ce badge est distribué sans aucune précaution : il n'a ni l'étiquette HttpOnly (qui interdit aux scripts voleurs de le lire), ni l'étiquette Secure (qui oblige à ne voyager que par tunnel sécurisé HTTPS).

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Nelly consulte son site depuis son smartphone ou son ordinateur portable connecté au Wi-Fi d'un café, d'une gare ou d'un salon immobilier. Sans l'attribut Secure, le cookie voyage en clair sur les ondes Wi-Fi : un pirate assis à la table voisine intercepte ce badge en 2 secondes et se connecte immédiatement sous l'identité de Nelly sans même avoir besoin de connaître son mot de passe ! De même, si un petit script publicitaire est compromis, il peut voler ce cookie via JavaScript car HttpOnly est absent.

👤 Impact Métier : Usurpation de l'identité de l'administratrice.
🚨 Sanction RGPD : Violation de données personnelles de clients mandants.
Ancien Site (www.nellimmo.fr) Badge Exposé

Le cookie de session PHP est envoyé nu. N'importe quel script JavaScript exécuté dans la page peut lire sa valeur, et il peut transiter sans cadenas sur un réseau non sécurisé. 

# Cookie délivré par l'ancien site :
set-cookie: PHPSESSID=8e9fit...; path=/
HttpOnly: ABSENT (Lisible par JavaScript `document.cookie`)
Secure:   ABSENT (Peut circuler en HTTP non chiffré)
SameSite: ABSENT (Vulnérable aux rebonds de clics CSRF)
Nouveau Nell'Immo (Vercel) Badge Blindé

Le cookie d'authentification du Cockpit est verrouillé : strictement invisible pour tout script (immunité XSS totale), et restreint aux communications HTTPS cryptées. 

# Cookie d'authentification du nouveau Middleware :
set-cookie: nellimmo_cockpit_auth=...; Path=/;
HttpOnly: OUI (Intouchable par tout script pirate)
Secure:   OUI (Uniquement via tunnel SSL chiffré)
SameSite: Lax (Protégé contre les fausses requêtes)

L'Exposition du Cockpit d'Administration (Le Cœur du Réacteur)

Contrôle d'Accès & Barrière HTTP 401
🎯 Vulgarisation & Risque Métier
Risque Métier Ultime : Perte Totale de Contrôle

Qu'est-ce que c'est ? Le Cockpit Nell'Immo est le centre névralgique de l'agence. C'est ici que sont gérés : la pige immobilière, les dossiers de location ALUR, les compromis de vente, le carnet d'adresses des propriétaires et le registre physique des clés et panneaux d'agences. Si la porte d'entrée de ce panneau d'administration est visible de tous sur internet, les robots pirates peuvent tester des milliers de combinaisons de mots de passe nuit et jour jusqu'à trouver la faille.

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Avant correction, un bouton rose très visible dans le pied de page du site permettait à n'importe qui de cliquer sur « Espace Cockpit », ouvrant directement une page demandant de s'inscrire ou de se connecter. Pire encore, un robot pirate scannant le web pouvait découvrir l'adresse /cockpit, analyser le code source téléchargé dans son navigateur et tenter des attaques par dictionnaire ou force brute sans qu'aucune barrière réseau ne vienne l'arrêter.

🔑 Sécurité des Biens : Risque de fuite des adresses précises et codes de boîtes à clés.
📁 Secret Professionnel : Vol des dossiers acquéreurs et mandats exclusifs.
Avant Remédiation Porte Grande Ouverte

L'URL /cockpit répondait avec un code HTTP 200 OK à n'importe quel inconnu. Le formulaire de création de compte et de connexion était servi publiquement à tous les robots. 

# Réponse serveur avant correction :
HTTP/1.1 200 OK
Bouton public dans le footer : <a href="/cockpit">Espace Admin</a>
--> La porte d'administration était signalée à tout le monde !
Après Remédiation en Production Vigile Infranchissable 401

Le bouton a été supprimé du pied de page. Un Middleware Edge bloque immédiatement toute requête vers /cockpit ou les API sensibles avec un mur HTTP 401 Unauthorized. 

# Test réel en direct sur https://nellimmo.vercel.app/cockpit :
HTTP/1.1 401 Unauthorized
Www-Authenticate: Basic realm="Espace Cockpit Administration"
X-Robots-Tag: noindex, nofollow, noarchive
--> L'intrus est refoulé avant même que la page ne se charge !

Le Stockage des Mots de Passe & Clés Privées dans le Navigateur

Cryptographie AES-GCM 256 bits & Dérivation PBKDF2
🎯 Vulgarisation & Risque Métier
Risque de Vol de Secrets : Très Élevé

Qu'est-ce que c'est ? Le navigateur web (Chrome, Safari, Edge) dispose de mémoires locales appelées localStorage et sessionStorage. C'est pratique pour retenir vos préférences, mais tout ce qui y est stocké peut être lu par n'importe quelle extension installée sur votre ordinateur (ex: traducteur, bloqueur de pub tiers vérolé, ou script injecté).

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Dans la version initiale, lorsqu'on déverrouillait le coffre-fort de l'agence, le code écrivait en toutes lettres { password: "MotDePasseDeNelly" } dans la mémoire de l'ordinateur, ainsi que les clés des passerelles de diffusion (comptes de transfert d'annonces vers SeLoger, LeBonCoin). Si Nelly installait une extension de navigateur quelconque ou si un tiers avait un accès physique temporaire à son ordinateur portable, tous les mots de passe maîtres de l'agence étaient lisibles en un clic.

🔐 Compromission : Vol des identifiants des portails immobiliers partenaires.
💳 Piratage d'API : Utilisation frauduleuse du crédit d'intelligence artificielle DeepSeek.
Avant Remédiation Mot de Passe en Clair

Le mot de passe de déverrouillage était conservé sous forme de texte lisible dans sessionStorage, et la clé d'agence dans localStorage. 

// Ancien code vulnérable :
sessionStorage.setItem('nellimo_vault_session_v1', 
  JSON.stringify({ password: e })); 
# Le mot de passe était visible par toute extension installée !
Après Remédiation en Production Sécurité Niveau Bancaire

Le mot de passe de Nelly n'est jamais écrit sur le disque. Il est transformé en une clé binaire AES-256 via 150 000 tours de hachage cryptographique PBKDF2 en mémoire vive éphémère. 

// Nouveau code ultra-sécurisé (lib/vault.ts) :
sessionStorage.removeItem('nellimo_vault_session_v1');
const rawKey = await crypto.subtle.exportKey('raw', cachedKey);
sessionStorage.setItem('nellimo_vault_session_v2', toBase64(rawKey));
# ZÉRO mot de passe lisible : clé cryptographique pure !

Le Partage de Ressources sans Contrôle (CORS Wildcard « * »)

En-tête Access-Control-Allow-Origin: *
🎯 Vulgarisation & Risque Métier
Risque de Pillage Commercial & Espionnage : Élevé

Qu'est-ce que c'est ? Normalement, les navigateurs interdisent à un site web tiers (par exemple www.site-pirate.com) d'envoyer des ordres ou de lire des données sur un autre site (comme nellimmo.fr). C'est la règle de cloisonnement du web. Mais sur l'ancien site de La Boîte Immo, le serveur envoie un « joker universel » (l'astérisque *), disant en substance : « J'autorise n'importe quel site internet du monde à interroger mes pages et lire mes réponses ».

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Une agence concurrente peu scrupuleuse ou un site d'annonces pirate peut intégrer un petit script sur sa propre plateforme pour aspirer en temps réel toutes les nouvelles annonces, prix et photos de Nell'Immo sans aucune restriction technique, ou écouter les réponses envoyées aux clients connectés.

📉 Impact Commercial : Pillage automatique des mandats et baisse du trafic web.
⚡ Surcharge Serveur : Consommation de bande passante par des robots non autorisés.
Ancien Site (www.nellimmo.fr) Portes Ouvertes aux Tiers

Le serveur Apache renvoie une autorisation universelle sans restriction d'origine, même sur la page d'accueil de l'agence. 

# En-têtes réels constatés sur l'ancien site :
access-control-allow-origin: *
access-control-allow-headers: Authorization, Content-Type
--> N'importe quel domaine étranger peut interroger le site !
Nouveau Nell'Immo (Vercel) Accès Strict & Verrouillé

Zéro wildcard permissif sur les flux sensibles. Les passerelles API exigent l'authentification préalable et rejettent catégoriquement toute tentative non autorisée.

La Divulgation des Versions Logicielles (Obsolescence 2020)

En-têtes Serveur & Reconnaissance d'Attaque
🎯 Vulgarisation & Risque Métier
Risque de Vulnérabilités Non Corrigées : Élevé

Qu'est-ce que c'est ? En sécurité informatique, la première règle est de ne jamais divulguer aux inconnus la marque et la version précise de ses logiciels. Si un serveur crie sur tous les toits : « J'utilise telle version sortie en octobre 2020 », les pirates n'ont plus qu'à consulter les catalogues publics de failles de sécurité (les CVE) pour savoir exactement comment pirater la machine sans faire d'effort.

⚠️ Scénario d'attaque concret pour Nelly Fernandez :

Les pirates informatiques ne ciblent pas les sites manuellement : ils envoient des robots scanners automatisés qui parcourent des millions de sites web en quête de versions obsolètes. Dès qu'un robot détecte un serveur Apache mutualisé avec une signature logicielle vieille de 6 ans, il lance automatiquement des attaques connues pour prendre le contrôle du serveur ou installer des redirections frauduleuses vers des sites de contrefaçon ou de casino en ligne.

📉 Référencement Google : Risque d'être blacklisté par Google pour « site piraté ».
⏳ Obsolescence : Impossibilité pour Nelly de faire corriger le problème par le sous-traitant.
Ancien Site (www.nellimmo.fr) Fiche Technique Offerte

L'hébergement de La Boîte Immo étale tous les détails de son architecture interne dans chaque réponse HTTP envoyée aux navigateurs.

Le réseau Vercel Edge masque toute trace technique interne. Les serveurs sont continuellement mis à jour de manière transparente sans aucune interruption de service.
