01

Le Clickjacking (Le Piège de la Feuille Transparente)

En-tête X-Frame-Options & CSP
🎈 Expliqué à un enfant

Imagine que tu es en train de jouer sur ta tablette. Un méchant joueur pose une feuille de plastique transparente sur ton écran. Sur cette feuille transparente, il a dessiné un gros bouton magique : « Clique ici pour gagner 1 000 bonbons ! 🍬 ». Mais en réalité, juste en-dessous sur ton vrai écran, il y a le bouton secret de ta maison : « Donner toutes mes clés à un inconnu ». Tu crois appuyer sur les bonbons, mais ton doigt appuie à travers la feuille transparente sur le bouton interdit ! C'est ça le Clickjacking.

Exemple réel : Sur un site immobilier non protégé, un pirate peut enfermer la page dans un faux jeu-concours transparent. Quand la directrice de l'agence clique sur « Jouer », elle supprime en réalité une annonce sans le savoir !
Ancien Site (www.nellimmo.fr) Vulnérable

Aucun en-tête X-Frame-Options ni de directive Content-Security-Policy. N'importe quel pirate peut enfermer l'ancien site dans une page transparente piégée. 

# En-têtes prélevés sur l'ancien site :
HTTP/1.1 200 OK
server: Apache
X-Frame-Options: [ABSENT !]
Content-Security-Policy: [ABSENT !]
--> La porte est ouverte à la feuille transparente !
Nouveau Nell'Immo (Vercel) Blindé A+

Le serveur ordonne à tous les écrans du monde : « Interdiction formelle de glisser mon site dans une boîte ou une feuille transparente ! » 

# En-têtes prélevés en direct sur le nouveau site :
HTTP/1.1 200 OK
X-Frame-Options: DENY
Content-Security-Policy: frame-ancestors 'none';
--> Écran blindé : impossible de poser une feuille piège !
02

Le Vol de Session (Le Badge Écrit au Marqueur sur le Front)

Cookie PHPSESSID sans HttpOnly / Secure
🎈 Expliqué à un enfant

Quand tu vas dans un parc d'attraction, le surveillant te donne un bracelet magique secret pour prouver que tu as payé ton entrée. Si tu écris le code secret de ton bracelet au gros marqueur rouge sur ton front, n'importe quel passant dans la rue peut le lire, le recopier sur son propre bras et entrer à ta place dans le manège pour te voler ta barbe à papa !

Exemple réel : Sur l'ancien site, le cookie d'entrée s'appelle PHPSESSID. Comme il n'a pas la mention secrète HttpOnly, n'importe quel petit virus ou script dans le navigateur peut le lire d'un coup avec une simple commande document.cookie et voler l'identité de l'utilisatrice !
Ancien Site (www.nellimmo.fr) Danger Fuite

Le cookie de connexion est distribué sans cadenas. Il n'a ni HttpOnly (protection contre le vol par JavaScript), ni Secure (obligation d'utiliser HTTPS), ni SameSite. 

# En-tête prélevé sur l'ancien site :
set-cookie: PHPSESSID=8e9fit...; path=/
HttpOnly: [NON] (Volable par JavaScript !)
Secure:   [NON] (Peut voyager sans cadenas !)
SameSite: [NON] (Vulnérable au CSRF)
Nouveau Nell'Immo (Vercel) Cadenassé

Le cookie de session Cockpit est scellé dans une boîte en métal blindée : aucun script ne peut le toucher, et il ne voyage qu'à travers un tunnel chiffré de très haute sécurité. 

# En-tête généré par le nouveau middleware :
set-cookie: nellimmo_cockpit_auth=...;
HttpOnly: [OUI] (Invisible pour les voleurs JS !)
Secure:   [OUI] (Uniquement sous cadenas SSL !)
SameSite: [Lax] (Protégé contre les faux clics)
03

L'Accès au Cockpit (La Salle des Commandes sans Clé)

Contrôle d'accès & Vigile d'Entrée
🎈 Expliqué à un enfant

Imagine que dans ton école, le bureau de la directrice (où il y a le grand carnet avec les secrets de tout le monde, les clés de toutes les salles et l'ordinateur central) n'avait aucune serrure sur la porte, et qu'une grosse flèche fluo dans la cour disait : « Entrez tous ici, appuyez sur les boutons ! ». Tout le monde pourrait y entrer et faire des bêtises !

Exemple réel : Sur l'ancien projet avant correction, l'adresse /cockpit s'ouvrait directement et un bouton rose fluo dans le pied de page invitait n'importe qui à créer un compte administrateur. Désormais, un grand vigile invisible se tient devant la porte.
Avant Correction Porte Ouverte

N'importe qui tapant /cockpit recevait un grand HTTP 200 OK. Les robots pouvaient tenter des millions de mots de passe sans jamais être arrêtés. 

# Réponse avant correction :
HTTP/1.1 200 OK

Créez votre compte administrateur

--> N'importe qui pouvait entrer et s'inscrire !
Après Remédiation en Production Vigile Actif

Le Middleware Vercel arrête l'intrus sur le palier. Sans le mot de passe maître de Nelly Fernandez, la porte reste fermée à double tour avec un HTTP 401. 

# Réponse constatée en direct sur https://nellimmo.vercel.app/cockpit :
HTTP/1.1 401 Unauthorized
Www-Authenticate: Basic realm="Espace Cockpit Administration"
X-Robots-Tag: noindex, nofollow, noarchive
Accès Restreint au Cockpit Nell'Immo
04

Le Coffre-Fort (Le Post-it sur la Table de Récréation)

Cryptographie & Secrets en Mémoire
🎈 Expliqué à un enfant

Tu as une boîte à secrets fermée par un cadenas à chiffres. Mais pour ne pas oublier ton code quand tu vas jouer à la marelle, tu écris ton code secret sur un papier jaune collé sur la table. Quand tu reviens, ton copain farceur a lu le papier et connaît ton mot de passe !

Exemple réel : L'ancien code du coffre-fort stockait { password: "MonMotDePasse" } en texte brut dans le sessionStorage du navigateur. Aujourd'hui, le mot de passe est immédiatement transformé par une formule mathématique secrète (PBKDF2 avec 150 000 calculs) et le vrai mot de passe est effacé de la mémoire !
Avant Remédiation Mot de passe en clair

Le mot de passe maître voyageait en clair dans sessionStorage et la clé d'agence dans localStorage. Des secrets de serveurs figuraient dans le code téléchargé. 

// Ancien code vulnérable :
sessionStorage.setItem('vault', 
  JSON.stringify({ password: e })); 
# Le mot de passe était visible par n'importe qui !
Après Remédiation Zéro Mot de Passe Écrit

Seul le tampon binaire brut d'une clé AES-GCM 256 bits est conservé en mémoire vive pour chiffrer les données. Le mot de passe de l'utilisatrice n'est jamais consigné. 

// Nouveau code ultra-sécurisé (lib/vault.ts) :
sessionStorage.removeItem('nellimo_vault_session_v1');
const rawKey = await crypto.subtle.exportKey('raw', cachedKey);
sessionStorage.setItem('session_v2', toBase64(rawKey));
# ZÉRO mot de passe lisible sur le disque !

Le CORS Permissif (Le Panneau « Entrée Gratuite pour Tous les Voisins »)

Access-Control-Allow-Origin: *
🎈 Expliqué à un enfant

Imagine que sur la porte de ta chambre, tu accroches une pancarte : « Avis magique avec une étoile (*) : n'importe quel enfant de la Terre a le droit d'envoyer un drone dans ma chambre pour regarder mes jouets et mes devoirs ». Les sites pirates d'en face peuvent alors envoyer des espions pour lire tes pages privées !

Exemple réel : Sur l'ancien site, l'en-tête renvoie Access-Control-Allow-Origin: *. N'importe quel site internet tiers peut envoyer des requêtes automatiques et lire les réponses de Nell'Immo sans barrière.
Ancien Site (www.nellimmo.fr) Wildcard Total

Le serveur Apache de La Boîte Immo retourne un joker universel sur la page d'accueil elle-même, autorisant tous les sites du web à écouter les échanges. 

# En-tête prélevé sur l'ancien site :
access-control-allow-origin: *
access-control-allow-headers: Authorization, Content-Type
--> Tous les sites étrangers sont autorisés à lire !
Nouveau Nell'Immo (Vercel) Accès Verrouillé

Aucun wildcard permissif. Les API privées exigent la présence du badge de session sécurisé sous peine d'un refus catégorique HTTP 401. 

# Test en direct sur une API sensible du nouveau site :
curl -i https://nellimmo.vercel.app/api/settings/ai-key
HTTP/1.1 401 Unauthorized
{"error":"unauthorized","message":"Accès restreint"}

La Fuite d'Informations (Donner le Plan de son Alarme aux Voleurs)

Fuite des En-têtes Serveur & Obsolescence
🎈 Expliqué à un enfant

Si tu installes une alarme sur ta maison et que tu écris sur la sonnette : « Attention, alarme modèle Dino-2020 version 2 ! », les voleurs vont chercher sur internet la notice de cette vieille alarme et sauront immédiatement quel petit fil couper pour l'éteindre sans faire de bruit !

Exemple réel : L'ancien site proclame fièrement qu'il utilise le moteur x-bobcat-version: kitty.pryde.20201020.rev2 (un système figé depuis octobre 2020) et le serveur cluster8-w3. Les pirates savent exactement quelles failles attaquer !
Ancien Site (www.nellimmo.fr) Détails Divulgués

L'ancien hébergement étale toutes ses informations techniques privées dans les réponses HTTP, facilitant le travail de repérage des cybercriminels. 

# En-têtes prélevés sur l'ancien site :
server: Apache
x-bobcat-version: kitty.pryde.20201020.rev2 (Date de 2020 !)
x-server-id: cluster8-w3
x-lbi-loadbalancer: cluster8-lb1
x-lbi-server: cluster8-w3
Nouveau Nell'Immo (Vercel) Silence Radio

Le serveur Vercel Edge masque entièrement les composants internes, empêchant toute analyse de vulnérabilité ciblée. 

# En-tête prélevé sur le nouveau site :
Server: Vercel
X-Content-Type-Options: nosniff
--> Aucune version logicielle interne n'est divulguée !
