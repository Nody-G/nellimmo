Détail Technique & Preuves Live d'Exécution

VULN-01

Verrouillage de la Route /cockpit par Middleware Edge

Résolu en Production
Avant Remédiation

La page /cockpit renvoyait un HTTP 200 OK directement à n'importe quel internaute ou crawler. Un bouton bien visible dans le footer public pointait directement sur cette interface, permettant à quiconque de lancer la procédure d'onboarding administrateur.

Après Remédiation

Le fichier middleware.ts s'exécute à l'Edge Vercel avant le rendu Next.js. Sans en-tête Authorization valide ou cookie de session nellimmo_cockpit_auth, l'accès est immédiatement bloqué avec un HTTP 401. Le bouton dans le footer a été remplacé par les horaires de l'agence.

Preuve de Test en Direct (Requête cURL sur l'URL de Production) :
> curl.exe -i https://nellimmo.vercel.app/cockpit

HTTP/1.1 401 Unauthorized
Www-Authenticate: Basic realm="Espace Cockpit Administration"
X-Frame-Options: DENY
X-Robots-Tag: noindex, nofollow, noarchive
Content-Type: text/plain; charset=utf-8

Accès Restreint au Cockpit Nell'Immo
VULN-02

Éradication des Secrets et Mots de Passe en Clair dans le Navigateur

Résolu en Production
Avant Remédiation

La fonction unlockVault enregistrait l'objet { password } en clair dans le sessionStorage. De plus, setAgencyKey stockait la clé d'agence en clair dans le localStorage. Des champs serveurs comme sftp_password et meta_app_secret figuraient dans le bundle JavaScript public.

Après Remédiation

Le mot de passe de l'utilisateur n'est plus jamais écrit dans le stockage du navigateur. Seul le tampon brut de la clé dérivée AES-GCM 256 bits est manipulé. La clé d'agence est isolée en RAM et session active. Les champs serveurs sont épurés des structures clientes.

Extrait du Code Source Durci (lib/vault.ts) :
// Seules les clés légitimes client-side sont exposées dans le bundle
export const SENSITIVE_SETTINGS_FIELDS: (keyof AgencySettings)[] = [
    'facebook_page_access_token',
    'google_maps_api_key',
];

export async function unlockVault(password: string): Promise<void> {
    // Nettoyage immédiat de tout vestige historique
    sessionStorage.removeItem('nellimo_vault_session_v1');
    cachedKey = await deriveKey(password);
    
    // Export du tampon binaire brut de la clé AES (JAMAIS le mot de passe utilisateur)
    const exportedRaw = await crypto.subtle.exportKey('raw', cachedKey);
    sessionStorage.setItem('nellimo_vault_session_v2', toBase64(exportedRaw));
}
VULN-03 & VULN-04

En-têtes HTTP de Sécurité & Protection Anti-Clickjacking

Résolu en Production
Avant Remédiation

Aucun en-tête X-Frame-Options ni Content-Security-Policy n'était retourné. Un attaquant pouvait insérer le site ou le cockpit dans une <iframe> invisible pour réaliser des attaques de détournement de clics (UI redressing / clickjacking).

Après Remédiation

Configuration complète dans next.config.ts. L'en-tête X-Frame-Options: DENY et la directive CSP frame-ancestors 'none' interdisent formellement toute intégration en iframe. La directive Permissions-Policy n'autorise le microphone que pour le domaine propre (self).

En-têtes HTTP Renvoyés par la Page d'Accueil Live :

X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(self), geolocation=()
X-XSS-Protection: 1; mode=block
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://va.vercel-scripts.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' data: blob: https://nellimmo.staticlbi.com https://images.unsplash.com https://api.qrserver.com; connect-src 'self' https://*.supabase.co https://api.mapbox.com https://api.deepseek.com https://va.vercel-scripts.com; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
VULN-05 & ADD

Protection Anti-Crawlers & Sécurisation des Routes API Sensibles

Résolu en Production
Avant Remédiation

Les routes /api/settings/ai-key, /api/deepseek/telemetry et /api/feeds/download étaient accessibles sans aucune authentification. Un visiteur anonyme pouvait écraser ou supprimer la clé DeepSeek, vider les crédits API ou télécharger les flux immobiliers sans token.

Après Remédiation

Toutes les routes d'API internes sont désormais sous le contrôle du middleware.ts et renvoient un HTTP 401 Unauthorized formaté en JSON pour toute requête non authentifiée. Le fichier app/robots.ts bloque l'indexation de /cockpit/ et /api/.

Preuves de Rejet sur les API Sensibles :
> curl.exe -i https://nellimmo.vercel.app/api/settings/ai-key
HTTP/1.1 401 Unauthorized
{"success":false,"error":"unauthorized","message":"Accès restreint aux utilisateurs authentifiés du Cockpit."}

> curl.exe -i https://nellimmo.vercel.app/api/feeds/download?feed=poliris
HTTP/1.1 401 Unauthorized
{"success":false,"error":"unauthorized","message":"Accès restreint aux utilisateurs authentifiés du Cockpit."}

> curl.exe -i https://nellimmo.vercel.app/robots.txt

Disallow: /cockpit/
Disallow: /api/

Checklist de Mise en Production (Tableau de bord Vercel)

Les correctifs de code sont d'ores et déjà déployés et actifs. Pour parachever la configuration de sécurité en production, voici les dernières actions à réaliser sur votre interface Vercel :

  • Configurer les Identifiants d'Administration Cockpit :
    Dans Vercel > Settings > Environment Variables, ajoutez COCKPIT_ADMIN_USER (ex: admin_nelly) et COCKPIT_ADMIN_PASSWORD (mot de passe robuste pour l'invite HTTP Basic).
  • Sécuriser les Jetons de Tâches Cron & Flux :
    Ajoutez CRON_SECRET pour la synchronisation SFTP, ainsi que CALENDAR_FEED_TOKEN, BIENICI_FEED_TOKEN et POLIRIS_FEED_TOKEN.
  • Basculer le Nom de Domaine Principal :
    Dans Vercel > Settings > Domains, reliez nellimmo.fr afin de finaliser la transition hors du sous-domaine partagé *.vercel.app.
